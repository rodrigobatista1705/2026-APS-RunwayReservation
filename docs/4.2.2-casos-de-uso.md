# 4.2.2 Modelagem de Casos de Uso

## Atores

Dois papéis usam o Runway Reservation. O ator é o papel, não a pessoa. Na Seção 4.1 aparecem professores e atletas utilizando a pista e os materiais esportivos. Embora sejam pessoas diferentes, ambos usam o sistema da mesma forma: consultam informações sobre os recursos esportivos e podem registrar devoluções de materiais. Por isso são representados por um único ator, chamado Usuário da pista.

Já o Prof. Miguel atua como administrador dos recursos esportivos. No diagrama, esse papel aparece como Responsável pela pista, conforme definido em "Quem usa" da Seção 4.1.

| Ator | Quem é | O que faz no sistema |
|---|---|---|
| Usuário da pista | professor, atleta ou outra pessoa autorizada a utilizar a pista e os materiais esportivos | consulta disponibilidade, consulta histórico e registra devolução |
| Responsável pela pista | servidor encarregado da administração da pista e dos materiais esportivos | cadastra materiais e usuários, registra empréstimos e reservas, consulta histórico e localiza materiais |


## Casos de uso

Cada caso de uso representa um objetivo que um ator alcança utilizando o sistema. Os nomes foram mantidos iguais aos requisitos funcionais para facilitar a rastreabilidade.

Nem todo requisito precisa representar uma ação visível do usuário. Entretanto, neste projeto, todos os requisitos funcionais correspondem diretamente a objetivos dos atores e, por isso, aparecem como casos de uso.

| Caso de uso | Ator | Atende |
|---|---|---|
| Cadastrar material | Responsável pela pista | RF01 |
| Cadastrar usuário | Responsável pela pista | RF02 |
| Consultar disponibilidade | Usuário da pista | RF03 |
| Registrar empréstimo | Responsável pela pista | RF04 |
| Identificar usuário | nenhum: é incluído por Registrar empréstimo e Registrar devolução | passo compartilhado pelos dois processos|
| Registrar devolução | Usuário da pista | RF05 |
|Consultar histórico| Responsável pela pista e Usuário da pista | RF06 |
| Localizar material | Responsável pela pista | RF07 |

## Especificação do caso de uso principal

Registrar empréstimos é o caso de uso que justificou a existência do sistema. O principal problema relatado pelo Prof. Miguel é dificuldade de controlar quem está utilizando os materiais esportivos e a pista em determinado momento. Registrar empréstimo e reservas substitui os controles feitos em papel e permite localizar rapidamente os responsáveis por cada recurso

| Campo | |
|---|---|
| Caso de uso | Registrar empréstimo |
| Ator | responsável pela pista |
| Pré-condição | O responsável pela pista deve estar autorizado a utilizar o sistema, o material deve estar cadastrado e o usuário deve possuir cadastro no sistema |
| Pós-condição | O empréstimo fica registrado no sistema, associado ao usuário e ao material, e a disponibilidade do material é atualizada |


**Fluxo principal**
1. O responsável pela pista acessa a funcionalidade Registrar empréstimo
2. O sistema solicita a identificação do usuário que receberá o material
3. O sistema executa o caso de uso identificar usuário, verificando se o usuário está cadastrado
4. O responsável pela pista seleciona o material que será emprestado
5. O sistema verifica se o material está disponível para o empréstimo
6. O responsável pela pista confirma o registro do empréstimo
7. O sistema registra o empréstimo, vinculando o material ao usuário identificado
8. O sistema atualiza a disponibilidade do material e apresenta uma confirmação do registro

**Fluxo alternativo**
- A1, no passo 5: o material não está disponível. O sistema informa que o material não pode ser emprestado naquele momento e permite que o responsável selecione outro material. O fluxo retorna ao passo 4.

**Fluxos de exceção**
- E1, no passo 3: o usuário não está cadastrado ou não pode ser identificado. O sistema informa que não foi possível identificar o usuário e encerra o caso de uso sem registrar o empréstimo
- E2, no passo 7: ocorre uma falha ao registrar o empréstimo. O sistema informa que não foi possível concluir a operação e encerra o caso de uso sem a pós-condição
- E3, no passo 5: ocorre uma falha ao consultar a disponibilidade do material. O sistema informa que não foi possível verificar a situação do material e encerra o caso de uso sem registrar o empréstimo
